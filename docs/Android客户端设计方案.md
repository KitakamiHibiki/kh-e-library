## 一、概述

### 1.1 定位

为自托管的个人电子书库（kitakami_hibiki e-library）提供 **Android 客户端**。服务端为单文件 Go 二进制（内嵌 Web 前端，默认端口 14325），Android 客户端作为**独立客户端**连接自托管的服务端，提供书架浏览、搜索、图书阅读（EPUB/PDF）、阅读进度同步、标签/书架管理、上传等能力。

### 1.2 目标用户

与 Web 端一致：自托管部署者本人，在手机/平板上阅读自己的电子书库。

### 1.3 目标

**原则：Android 功能与 Web 端基本一致**，覆盖书库的完整管理、阅读与设置能力；在此之上再叠加移动端特有增强。

- **P0（首版，与 Web 功能对齐）**：
  - 前置：配置服务端根地址（**进入 App 的强制门槛**，未配置不允许进入任何功能）；所有接口基于该根地址。
  - 书架：浏览 / 关键字搜索 / 标签与状态筛选 / 排序 / 分页 / **批量删除**。
  - 图书：详情与图书信息弹窗、卡片操作菜单（阅读/图书信息/标记已读或未读/加入书架/导出分享/删除）、**重新解析**、阅读状态切换。
  - 阅读：EPUB（单/双栏、目录、字号、深色模式）与 PDF（缩放、单页/双页/连续滚动、页码跳转）；阅读进度自动保存与断点续读；阅读完成页。
  - **标签/书架管理**：增删改、图书关联、创建书架、"未放入书架"筛选。
  - **上传**：EPUB/PDF 上传（含分片）。
  - **运行时设置**：读写服务端共享设置（主题、语言、排序、字号、阅读器视图、存储目录），与 Web 端行为一致。
  - **统计**：书架概览。
  - **软件更新**：检查/下载/安装，与 Web 端一致（见 §6.9）。
- **P2（可选增强，Web 端没有的移动端能力）**：离线缓存与纯离线阅读；上传/阅读通知；桌面小部件；多服务端配置。

### 1.4 非目标（明确不做）

- **不在 Android 端内置服务端**（后端部署方式维持现状：单机二进制 / Docker）。
- **不做登录 / 认证**（个人自部署自用，服务端当前也无认证；若未来暴露公网再评估，见 §4.3）。
- 不做云同步/多端账号体系（服务端为单用户自托管，无用户系统）。
- 不做 iOS 版本（本方案仅 Android）。

## 二、现状与约束

### 2.1 服务端 API 清单（现成可复用）

| 分组 | 端点 | 用途 |
|------|------|------|
| 健康 | `GET /health` | 连通性检查 |
| 图书 | `GET /books/list` | 列表（分页/关键字/标签/状态/排序） |
| 图书 | `GET /books/detail?id=` | 单本详情 |
| 图书 | `POST /books/create` | 上传（multipart） |
| 图书 | `POST /books/create/chunk/init` · `/chunk` | 分片上传 |
| 图书 | `POST /books/update?id=` | 更新标题/作者/出版社/阅读状态 |
| 图书 | `POST /books/reprocess?id=` | 重新解析 |
| 图书 | `POST /books/delete?id=` · `/batch_delete` | 删除 / 批量删除 |
| 图书 | `GET /books/read?id=` | 阅读文件流（**支持 HTTP Range**） |
| 图书 | `GET /books/download?id=` | 下载（整文件，无 Range） |
| 图书 | `GET /books/cover?id=` | 封面图 |
| 进度 | `GET /books/progress?id=` · `POST /books/progress/save` | 阅读进度读写 |
| 标签 | `GET /tags/list` · `POST /tags/create` · `/update` · `/delete` | 标签管理 |
| 图书标签 | `POST /books/tags/add` · `/remove` | 图书-标签关联 |
| 设置 | `GET /settings/list` · `POST /settings/update` | 运行时设置 |
| 统计 | `GET /stats/overview` | 书架概览 |
| 系统 | `GET /system/status` | 版本与运行状态 |
| 更新 | `GET /system/check-update` · `POST /system/start-update` · `GET /system/update-status` | 软件更新（**服务端自身更新，Android 端仅只读展示**） |

### 2.2 图书数据模型（服务端 `model.Book`）

`id / title / author / publisher / isbn / cover / file / file_type(epub|pdf) / file_size / file_hash / description / language / tags[] / pages(EPUB章节数|PDF页数) / storage_key / read_status(unread|reading|finished) / book_status(processing|failed|ready|deleted) / created_at / updated_at`

### 2.3 关键约束

1. **个人自部署自用，服务端无认证，Android 端暂不引入认证**（见 §4.3 遗留说明）。
2. **所有接口必须通过用户配置的服务端根地址访问**，客户端不得硬编码地址；进入 App 前强制完成根地址配置（见 §4）。
3. `GET /books/read` 支持 HTTP Range，阅读器可**按需流式加载** EPUB，无需整文件下载。

## 三、总体架构

### 3.1 模式：客户端-服务器

```
┌─────────────────────────┐          ┌────────────────────────────┐
│   Android 客户端         │   HTTP/   │   自托管服务端 (Go 单文件)   │
│  ┌─────────────────────┐ │  HTTPS 请求│   ┌──────────────────────┐ │
│  │ UI (Jetpack Compose) │ │ ────────▶ │   │ REST API (Gin)       │ │
│  │ 状态管理 (ViewModel)  │ │  baseUrl  │   │  SQLite + 本地文件     │ │
│  │ 数据层 (Repository)   │ │ ◀──────── │   └──────────────────────┘ │
│  │ 网络层 (Retrofit)     │ │  响应     │                            │
│  │ 本地缓存 (Room)       │ │          │                            │
│  └─────────────────────┘ │          │                            │
└─────────────────────────┘          └────────────────────────────┘
```

- **服务端根地址是 App 运行的前提**：进入 App 时若未配置合法根地址，强制停留在配置页，不允许进入任何功能；所有请求均以该根地址为 baseURL 发起（见 §4）。
- 客户端为**在线优先（online-first）**：列表/详情实时请求；仅将已读过的书籍文件缓存到本地，实现离线阅读（见 §7）。

### 3.2 分层

| 层 | 职责 | 技术 |
|----|------|------|
| UI | 页面、导航、组件 | Jetpack Compose + Material 3 |
| 状态 | 页面状态、UI 事件 | ViewModel + Kotlin Flow + StateFlow |
| 数据 | 业务逻辑、数据聚合 | Repository 层 |
| 网络 | REST 调用、错误处理、**根地址 baseURL 统一配置** | Retrofit + OkHttp + kotlinx.serialization |
| 缓存 | 书单/图书/进度的本地副本 | Room + DataStore |
| 阅读 | EPUB/PDF 渲染、进度上报 | 见 §5.3 阅读引擎选型 |

### 3.3 依赖注入

Hilt（Google 标准方案），便于测试与模块解耦。

## 四、服务端根地址配置与网络访问

> 个人自部署自用，**暂不引入任何认证**。本节聚焦"服务端根地址"这一 App 运行的前提配置。

### 4.1 根地址强制配置（进入 App 的门槛）

- **启动流程**：进入首页（书架）前，先校验本地是否已配置有效的服务端根地址。
  - 已配置 → 直接进入书架；
  - 未配置 / 配置为空 → **强制进入"服务器设置"页**，未填写合法根地址前**不允许进入任何其他页面/功能**。
- 合法性校验：非空、以 `http://` 或 `https://` 开头、能解析出主机与端口；提供「测试连接」调用 `GET /health` 与 `GET /system/status` 确认可达。
- 校验不通过给出明确提示，停留在设置页直至填写正确。

### 4.2 根地址的使用方式

- 根地址持久化到本地（DataStore），**App 内所有接口请求的 baseURL 均动态取自该根地址**，统一拼装：`<根地址>/api/v1/<endpoint>`。
- 网络层以该根地址构造唯一的 OkHttp / Retrofit 实例；设置页可修改根地址，修改后**重建网络实例并刷新全部页面**。
- 封面 / 阅读流 / 下载等资源 URL 同样基于根地址拼装（`/api/v1/books/cover?id=` 等），不允许硬编码。

### 4.3 认证（遗留说明，暂不实现）

- 当前服务端无认证，Android 端也不携带任何令牌 / 账号信息。
- 若未来服务端引入认证，客户端在 OkHttp 层预留统一的请求拦截器扩展点，届时接入即可，不影响现有结构。

## 五、技术选型

### 5.1 基础

| 项 | 选型 | 说明 |
|----|------|------|
| 语言 | Kotlin 2.x | 官方推荐 |
| UI | Jetpack Compose + Material 3 | 声明式 UI，主题/深色模式原生支持 |
| 最低系统 | minSdk 26（Android 8.0） | 覆盖 95%+ 设备；如需更广可降 24 |
| 目标系统 | targetSdk 35（Android 15） | 适配最新行为变更 |
| 架构 | MVVM + Repository | 单 Activity + Navigation Compose |
| 异步 | Coroutines + Flow | 统一异步模型 |

### 5.2 数据/网络库

| 用途 | 选型 |
|------|------|
| HTTP | Retrofit 2 + OkHttp 4 |
| 序列化 | kotlinx.serialization（或 Moshi） |
| 封面图片 | Coil |
| 本地数据库 | Room（书单/进度缓存） |
| 键值存储 | DataStore（偏好 / 服务端根地址） |
| 依赖注入 | Hilt |

### 5.3 阅读引擎选型（核心决策）

**原则：尽可能使用 Android 原生渲染，不套 WebView 壳。** 阅读器是体验的核心，以下为选型对比：

| 方案 | EPUB | PDF | 优点 | 缺点 | 结论 |
|------|------|-----|------|------|------|
| **A. 原生工具包（采用）** | **Readium Kotlin Toolkit** | **AndroidPdfViewer** | 原生 API、可深度定制主题/字号/翻页/书签；离线；体验最佳 | EPUB 渲染内部仍基于 WebView 封装（Android 无成熟的纯原生 EPUB 渲染器）；接入成本中等 | ⭐ **采用** |
| B. WebView + 本地内核 | epub.js 打包进 assets | pdf.js 或 AndroidPdfViewer | 实现快、与 Web 端对齐 | 非原生渲染，需手写桥接，可维护性差 | 备选（不优先） |
| C. WebView 直连服务端 Web UI | 复用现有 Web 前端 | 复用现有 Web 前端 | 零重实现 | 现有 Web UI 未适配手机，体验差；依赖网络 | 不采用 |

**说明：**
- **EPUB**：Android 生态没有成熟的"纯原生（非 WebView）"EPUB 渲染器（EPUB 的 XHTML/CSS 排版只能由浏览器内核完成）。**Readium Kotlin Toolkit** 是行业标准原生工具包：对外为原生 Kotlin API（翻页、目录、书签、进度、深色主题、字号均为原生接口），内部以 WebView 渲染 EPUB 内容，是"原生优先"原则下的最佳选择。备选：EpubKit（Kotlin Multiplatform、免 WebView，但较新、生态小）。
- **PDF**：**AndroidPdfViewer**（barteksc）提供手势缩放、双页、连续滚动；或框架级 `PdfRenderer`（轻量但能力有限）。

**阅读前文件获取：**
- 打开书籍时经 `GET /books/read` 将书籍文件下载到本地缓存，再交由原生阅读器渲染本地文件。
- 好处：渲染稳定、翻页/进度流畅；已打开过的书天然支持离线阅读。

> ⚠️ **决策点 D2**：EPUB 渲染库最终选型（默认 Readium Kotlin Toolkit）。

### 5.4 关键兼容性说明

- **EPUB（Readium）**：支持 CFI 定位与断点续读、TOC 目录、字号/主题/翻页动画原生配置；EPUB 3 固定版式（FXL）与图片类（漫画）EPUB 需专项验证。
- **PDF（AndroidPdfViewer）**：手势缩放/翻页原生支持；大文件注意内存（`pageFits`、分段渲染等参数）。

## 六、功能需求

> 优先级：**P0=首版必须**（与 Web 端功能对齐） **P2=可选增强**（Web 端没有的移动端能力）。

### 6.1 服务端根地址配置（P0，进入 App 的前置门槛）

- **启动门槛**：进入书架前校验本地已配置的服务端根地址；未配置则**强制**停留在"服务器设置"页，未填写合法根地址不允许进入任何其他页面。
- 设置项：服务端根地址（含协议与端口，如 `http://192.168.1.10:14325`）。
- 「测试连接」：调用 `GET /health` 与 `GET /system/status` 校验连通。
- **所有接口均基于该根地址访问**（见 §4）；设置页可随时修改，修改后重建网络实例并刷新页面。
- 断网时给出明确提示并可跳回配置页。

### 6.2 书架（P0）

- 展示图书网格（封面 + 标题 + 作者 + 阅读状态角标）；封面走 `GET /books/cover?id=`（Coil + 磁盘缓存）。
- 支持：分页加载（每页数量可配置，默认 20）、上滑加载更多、下拉刷新。
- 搜索：按书名/作者关键字，防抖 300ms 请求 `GET /books/list?keyword=`。
- 排序：更新时间/书名/作者/创建时间 × 升降序（默认更新时间降序）。
- 筛选：按标签（书架）、按"未放入书架"；状态筛选（全部/在读/已读/未读）。
- 长按卡片弹出操作菜单：阅读 / 图书信息 / 标记已读（或未读）/ 加入书架 / 导出（分享文件）/ 删除。
- **批量删除**：长按进入多选模式，勾选后删除（`POST /books/batch_delete`），与 Web 端一致。
- 处理中（processing）/ 失败（failed）状态卡片的展示与「重新处理」入口。

### 6.3 图书详情（P0）

- 封面大图、标题、作者、标签；字段：类型/大小/章节数（或页数）/ISBN/出版社/语言/添加/更新时间；简介。
- 底部操作：阅读（主按钮）、导出/分享、加入书架。

### 6.4 阅读器-EPUB（P0）

- 渲染：章节流式渲染（基于本地缓存文件），支持**单栏/双栏**。
- 目录：章节侧滑抽屉导航，点击跳转 CFI。
- 进度：随翻页自动保存（防抖 2s）→ `POST /books/progress/save`（`cfi` + `progress`）。
- 续读：打开书籍时 `GET /books/progress?id=` 恢复 CFI 位置。
- 字号调整（可记忆）、**深色模式**（跟随系统主题）。
- 阅读完成页：翻到最后一页后进入完成页 → 「标记已读完」/「再读一遍」/「返回原尾页」。

### 6.5 阅读器-PDF（P0）

- 渲染：原生 PDF 视图，支持**单页 / 双页 / 连续滚动**；手势缩放（25%~300%）、适应宽度。
- 页码跳转：页码输入框；进度 = 当前页/总页数，自动保存（页码存 `cfi` 字段）。
- 续读：恢复上次页码。
- 阅读完成页：与 EPUB 一致。

### 6.6 标签与书架管理（P0，与 Web 一致）

- 侧栏导航：全部图书 / 书架列表（含创建书架、每格数量）/ 未放入书架，与 Web 端一致。
- 标签管理：新建 / 重命名 / 删除标签（`/tags/*`）。
- 图书"加入书架"对话框：多选/取消标签，支持即时新建标签，与 Web 端交互一致。

### 6.7 上传图书（P0，与 Web 一致）

- 从系统文件选择器/文件管理器选取 `.epub` / `.pdf`。
- 大文件（> 阈值，如 20MB）走**分片上传**（`/books/create/chunk/init` + `/chunk`，逐片上传并显示进度）；小文件直接 `POST /books/create`。
- 上传中显示进度条，可取消；完成后刷新书架并提示。

### 6.8 统计与设置（P0，与 Web 一致）

- 统计概览：总书数 / 未读 / 在读 / 已读（`GET /stats/overview`），与 Web 端一致。
- **运行时设置读写服务端共享设置**（`GET/POST /settings/list`、`/update`）：主题、语言、排序、每页数量、阅读字号、阅读器视图、存储目录等，行为与 Web 端一致（见 §7.4）。
- 客户端本地设置：仅保留设备相关项（服务端根地址、"跟随系统"主题开关）。

### 6.9 软件更新（P0，与 Web 一致）

- 设置页提供"检查更新"入口（`GET /system/check-update`），展示当前/最新版本、更新说明，与 Web 端一致。
- 支持**下载并安装**（`POST /system/start-update` + `GET /system/update-status`）：与 Web 端共用同一套接口与交互；安装完成后服务端优雅重启，客户端自动进入"重连中"状态并恢复书架。
- 安装为破坏性操作，需二次确认（与 Web 端"全部操作需用户确认"一致）。

## 七、数据与同步设计

### 7.1 本地数据模型（Room）

| 表 | 字段 | 说明 |
|----|------|------|
| `book_cache` | 与 `model.Book` 一致 + `local_file_path` / `updated_at` | 已打开过的书单快照与文件缓存 |
| `reading_progress` | `book_id / progress / cfi / chapter_href / updated_at` | 本地进度兜底（服务端为准） |
| `server_config` | `base_url` | 服务端根地址（DataStore 持久化） |

### 7.2 缓存策略

- **列表不长期缓存**：书架/搜索结果实时请求，仅用内存态 + 短 TTL（如 30s）减少重复请求。
- **封面**：Coil 磁盘缓存，服务端封面变更时以 `file_hash` 或时间戳作缓存键。
- **书籍文件**：仅缓存**用户打开过**的书到应用私有目录；提供「管理缓存」入口（查看占用、清理）。单个文件大小上限建议 500MB，超出提示用流式加载。

### 7.3 进度同步

- **在线优先**：每次翻页防抖后写入服务端；服务端为唯一权威。
- 打开书籍时先读服务端进度恢复；网络失败时回退本地进度。
- 无冲突合并需求（单用户），以"最近写入时间"为准。

### 7.4 多端设置共享

- **按"功能与 Web 一致"原则，Android 端直接读写服务端运行时设置**，与 Web 端共享同一份配置、行为一致（单用户、单服务端，以最近写入为准，无需冲突合并）。
- 仅设备相关项存客户端本地（服务端根地址、"跟随系统"主题开关等）。

## 十、开发计划

### 阶段 0：项目脚手架（约 1 周）
- Compose + Hilt + Retrofit + Room 骨架；**服务端根地址强制配置流程**（进入 App 的门槛，见 §4.1）；网络层按根地址动态构建。

### 阶段 1：MVP（与 Web 功能对齐，约 6-8 周）
1. 服务端根地址配置页（强制门槛）+ 网络层（基于根地址 baseURL）。
2. 书架（网格/搜索/筛选/排序/分页/批量删除）、图书详情、卡片操作菜单、阅读状态切换、重新解析。
3. EPUB 阅读（Readium 原生集成 + 本地文件加载 + 进度同步/续读 + 目录 + 字号/深色 + 单双栏）。
4. PDF 阅读（AndroidPdfViewer 原生渲染 + 缩放/翻页/连续滚动 + 进度同步）。
5. 阅读完成页；标签/书架管理（增删改、关联、创建书架）。
6. 上传（含分片）；统计概览；运行时设置（读写服务端共享设置）；软件更新（检查/下载/安装）。
7. 主题与中英语言；缓存管理。

### 阶段 2：完善（约 3-4 周）
- 移动端体验打磨：阅读手势、深色模式细节、设置项完整化、批量删除交互、错误处理与重连、阅读性能优化。

### 阶段 3：可选增强
- 离线缓存增强、通知/深链、桌面小部件、多服务端配置。

## 十一、关键决策点（已确认）

| 编号 | 决策 | 结论 |
|------|------|------|
| D1 | 认证 | **不做**（个人自部署自用，暂不引入；后续暴露公网再评估，见 §4.3） |

| D5 | 最低支持系统版本 | minSdk 26（Android 8.0） |
| D6 | 上传分片阈值 | 20MB（小文件直传，大文件分片） |
