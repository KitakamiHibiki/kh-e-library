# kh e-library 数据迁移方案

## 1. 概述

本文档描述 kh e-library 数据库 Schema 变更的迁移策略。本软件使用 SQLite + GORM，当前通过 `AutoMigrate` 自动处理表结构变更。随着版本迭代，需要建立更严谨的版本化迁移机制，确保数据安全、可追溯、可回滚。

---

## 2. 当前状态分析

### 2.1 现有数据模型

当前共 5 张表：

| 表名 | 模型 | 说明 |
|------|------|------|
| `books` | `model.Book` | 图书信息（ID、标题、作者、文件路径、阅读状态等） |
| `tags` | `model.Tag` | 标签（ID、名称） |
| `book_tags` | `model.BookTag` | 图书-标签关联（多对多） |
| `reading_progresses` | `model.ReadingProgress` | 阅读进度（每书一条） |
| `settings` | `model.Setting` | 配置键值对 |

### 2.2 当前迁移方式

使用 GORM 的 `AutoMigrate`，实现在 `repository/db.go`：

```go
db.AutoMigrate(
    &model.Book{},
    &model.Tag{},
    &model.BookTag{},
    &model.ReadingProgress{},
    &model.Setting{},
)
```

**局限性**：
- ✅ 能自动创建新表
- ✅ 能自动添加新列
- ❌ 不能删除列
- ❌ 不能修改列类型
- ❌ 不能重命名列
- ❌ 不能添加复杂约束或索引
- ❌ 不可追溯、不可回滚
- ❌ 无版本记录

## 3. 迁移方案设计

### 3.1 Schema 版本管理

在 `settings` 表中引入 `schema.version` 键，记录当前数据库结构版本号。

| schema_version | 对应版本 | 变更内容 |
|----------------|----------|----------|
| 1 | v0.1.0 | 初始表结构（books, tags, book_tags, reading_progresses, settings） |
| 2 | v0.2.0 | （示例）books 表新增 `last_read_at` 列 |
| 3 | v1.0.0 | （示例）新增 `bookmarks` 表 |

### 3.2 迁移脚本格式

每个迁移由一个 Go 函数实现，包含 `Up`（正向）和 `Down`（回滚）两个方法：

```go
package migration

type Migration struct {
    Version     int       // 目标 schema 版本号
    Description string    // 迁移描述
    Up          func(db *gorm.DB) error
    Down        func(db *gorm.DB) error
}
```

**迁移脚本目录结构**：

```
backend/
├── internal/
│   ├── migration/
│   │   ├── migrator.go        # 迁移执行器
│   │   ├── registry.go        # 迁移注册表
│   │   ├── v0001_initial.go   # Schema v1：初始表结构
│   │   ├── v0002_book_last_read.go  # Schema v2：新增列
│   │   └── v0003_bookmarks.go # Schema v3：新增表
```

### 3.3 迁移执行器

```go
package migration

type Migrator struct {
    db         *gorm.DB
    migrations []Migration // 按 Version 升序排列
}

// Run 执行所有待执行的迁移
func (m *Migrator) Run() error {
    currentVersion := m.getCurrentVersion()

    for _, mig := range m.migrations {
        if mig.Version <= currentVersion {
            continue // 已执行，跳过
        }

        log.Printf("migrating schema: v%d → v%d (%s)", currentVersion, mig.Version, mig.Description)

        // 在事务中执行迁移
        err := m.db.Transaction(func(tx *gorm.DB) error {
            if err := mig.Up(tx); err != nil {
                return err
            }
            // 更新 schema 版本
            return tx.Model(&model.Setting{}).
                Where("key = ?", "schema.version").
                Upsert(&model.Setting{Key: "schema.version", Value: fmt.Sprintf("%d", mig.Version)})
        })

        if err != nil {
            return fmt.Errorf("migration v%d failed: %w", mig.Version, err)
        }

        currentVersion = mig.Version
        log.Printf("migration v%d completed successfully", mig.Version)
    }

    return nil
}

// Rollback 回滚到指定版本
func (m *Migrator) Rollback(targetVersion int) error {
    currentVersion := m.getCurrentVersion()

    // 逆序执行 Down
    for i := len(m.migrations) - 1; i >= 0; i-- {
        mig := m.migrations[i]
        if mig.Version > currentVersion || mig.Version <= targetVersion {
            continue
        }

        log.Printf("rolling back schema: v%d → v%d (%s)", currentVersion, mig.Version-1, mig.Description)

        err := m.db.Transaction(func(tx *gorm.DB) error {
            if err := mig.Down(tx); err != nil {
                return err
            }
            return tx.Model(&model.Setting{}).
                Where("key = ?", "schema.version").
                Update("value", fmt.Sprintf("%d", mig.Version-1))
        })

        if err != nil {
            return fmt.Errorf("rollback v%d failed: %w", mig.Version, err)
        }

        currentVersion = mig.Version - 1
    }

    return nil
}

// getCurrentVersion 从 settings 表读取当前 schema 版本
func (m *Migrator) getCurrentVersion() int {
    var setting model.Setting
    if err := m.db.Where("key = ?", "schema.version").First(&setting).Error; err != nil {
        return 0 // 未初始化
    }
    v, _ := strconv.Atoi(setting.Value)
    return v
}
```

### 3.4 迁移注册表

```go
package migration

var registry = []Migration{
    {
        Version:     1,
        Description: "initial schema",
        Up:          v0001Up,
        Down:        v0001Down,
    },
    // 后续迁移在此注册，按 Version 升序
}

func GetMigrations() []Migration {
    return registry
}
```

## 4. 迁移脚本示例

### 4.1 初始 Schema (v1)

```go
package migration

import "gorm.io/gorm"

func v0001Up(db *gorm.DB) error {
    return db.AutoMigrate(
        &model.Book{},
        &model.Tag{},
        &model.BookTag{},
        &model.ReadingProgress{},
        &model.Setting{},
    )
}

func v0001Down(db *gorm.DB) error {
    return db.Migrator().DropTable(
        "reading_progresses",
        "book_tags",
        "tags",
        "books",
        "settings",
    )
}
```

### 4.2 新增列 (v2) — 示例

```go
package migration

import "gorm.io/gorm"

func v0002Up(db *gorm.DB) error {
    return db.Exec("ALTER TABLE books ADD COLUMN last_read_at INTEGER DEFAULT 0").Error
}

func v0002Down(db *gorm.DB) error {
    // SQLite 不支持 DROP COLUMN（3.35.0 之前），需重建表
    return db.Exec(`
        CREATE TABLE books_backup AS SELECT
            id, title, author, publisher, isbn, cover_file, file,
            file_type, file_size, file_hash, description, language,
            pages, storage_key, read_status, book_status,
            created_at, updated_at
        FROM books
    `).Error
    // ... 后续：DROP books, RENAME books_backup TO books, 重建索引
}
```

### 4.3 新增表 (v3) — 示例

```go
package migration

import "gorm.io/gorm"

type Bookmark struct {
    ID        uint   `json:"id" gorm:"primaryKey"`
    BookID    uint   `json:"book_id" gorm:"not null;index"`
    CFI       string `json:"cfi" gorm:"not null"`
    ChapterHref string `json:"chapter_href"`
    Note      string `json:"note" gorm:"type:text"`
    CreatedAt int64  `json:"created_at"`
}

func v0003Up(db *gorm.DB) error {
    return db.AutoMigrate(&Bookmark{})
}

func v0003Down(db *gorm.DB) error {
    return db.Migrator().DropTable("bookmarks")
}
```

## 5. 迁移与现有 AutoMigrate 的过渡

### 5.1 过渡策略

当前 v0.1.0 使用 `AutoMigrate`，没有 `schema.version` 记录。需要一次引导迁移：

```go
func v0001Up(db *gorm.DB) error {
    // 检查 settings 表是否已有 schema.version
    var count int64
    db.Model(&model.Setting{}).Where("key = ?", "schema.version").Count(&count)

    if count == 0 {
        // 首次迁移：现有表已由 AutoMigrate 创建
        // 仅写入版本号，不重复建表
        db.Create(&model.Setting{
            Key:   "schema.version",
            Value: "1",
        })
    }

    // 确保所有表存在（兼容全新安装）
    return db.AutoMigrate(
        &model.Book{},
        &model.Tag{},
        &model.BookTag{},
        &model.ReadingProgress{},
        &model.Setting{},
    )
}
```

### 5.2 InitDB 改造

将 `repository/db.go` 中的 `AutoMigrate` 替换为迁移执行器调用：

```go
func InitDB(dsn string) *gorm.DB {
    // ... 打开数据库连接 ...

    // 替换 AutoMigrate 为迁移执行器
    migrator := migration.NewMigrator(db, migration.GetMigrations())
    if err := migrator.Run(); err != nil {
        log.Fatalf("failed to run migrations: %v", err)
    }

    // ... 启动修复等 ...
}
```

## 6. 数据安全策略

### 6.1 迁移前备份

每次执行迁移前自动备份数据库文件：

```
data/
├── .backup/
│   ├── schema_v1_20260807_120000.db    # 迁移前备份
│   └── schema_v1_20260807_120000.meta  # 备份元数据
```

**备份元数据**：

```json
{
    "original_db": "e-library.db",
    "schema_version_before": 1,
    "schema_version_after": 2,
    "backup_time": "2026-08-07T12:00:00Z",
    "db_size": 1048576,
    "sha256": "abc123..."
}
```

### 6.2 迁移事务保证

- 每个迁移在独立数据库事务中执行
- 迁移失败时事务自动回滚
- `schema.version` 在同一事务中更新，确保一致性

### 6.3 迁移校验

迁移完成后执行数据完整性校验：

```go
func validateAfterMigration(db *gorm.DB, version int) error {
    // 1. 检查所有表是否存在
    tables := []string{"books", "tags", "book_tags", "reading_progresses", "settings"}
    for _, t := range tables {
        if !db.Migrator().HasTable(t) {
            return fmt.Errorf("missing table: %s", t)
        }
    }

    // 2. 检查 schema.version 与预期一致
    var setting model.Setting
    db.Where("key = ?", "schema.version").First(&setting)
    if setting.Value != fmt.Sprintf("%d", version) {
        return fmt.Errorf("schema version mismatch: got %s, want %d", setting.Value, version)
    }

    // 3. 检查关键列是否存在
    // ... 版本特定的校验 ...

    return nil
}
```

## 7. SQLite 特殊处理

### 7.1 ALTER TABLE 限制

SQLite 对 `ALTER TABLE` 的支持有限：

| 操作 | 支持 | 备注 |
|------|------|------|
| ADD COLUMN | ✅ | 不能添加 PRIMARY KEY 或 UNIQUE 约束 |
| RENAME COLUMN | ✅ | SQLite 3.25.0+ |
| DROP COLUMN | ✅ | SQLite 3.35.0+ |
| 修改列类型 | ❌ | 需重建表 |
| 添加约束 | ❌ | 需重建表 |

### 7.2 表重建模板

当需要修改列类型或删除列（SQLite < 3.35.0）时，使用表重建模式：

```sql
-- 1. 创建新表
CREATE TABLE books_new (
    id INTEGER PRIMARY KEY,
    title TEXT NOT NULL,
    -- ... 新的列定义 ...
);

-- 2. 复制数据
INSERT INTO books_new SELECT id, title, ... FROM books;

-- 3. 删除旧表
DROP TABLE books;

-- 4. 重命名新表
ALTER TABLE books_new RENAME TO books;

-- 5. 重建索引
CREATE INDEX idx_books_title ON books(title);
```

### 7.3 WAL 模式

数据库使用 WAL（Write-Ahead Logging）模式，确保迁移期间的数据安全和并发读取能力：

```go
gorm.Open(sqlite.Open(dsn+"?_journal_mode=WAL&_busy_timeout=5000"), ...)
```

## 9. 文件数据迁移

除了数据库 Schema 变更，图书文件存储也可能需要迁移。

### 9.1 存储目录变更

当 `storage.local.books_dir` 设置变更时，需要将现有图书文件移动到新目录：

```go
func (s *BookService) OnSettingsChanged(changed map[string]string) error {
    if _, ok := changed["storage.local.books_dir"]; ok {
        newDir := s.settingRepo.GetWithDefault(model.SettingStorageBooksDir)
        oldDir := /* 当前存储目录 */

        if oldDir != newDir {
            // 1. 创建新目录
            os.MkdirAll(newDir, 0755)

            // 2. 遍历所有图书，移动文件
            books, _ := s.bookRepo.ListAll()
            for _, book := range books {
                oldPath := filepath.Join(oldDir, fmt.Sprintf("%d", book.ID))
                newPath := filepath.Join(newDir, fmt.Sprintf("%d", book.ID))
                os.Rename(oldPath, newPath)
            }
        }

        // 3. 重新初始化驱动
        driver, _ := storage.NewLocalDriver(newDir)
        s.factory.Register("local", driver)
    }
    return nil
}
```

### 9.2 文件格式转换

若未来支持新的存储格式（如从 ZIP 迁移到单独文件），迁移脚本需：

1. 读取旧格式文件
2. 转换为新格式
3. 写入新文件
4. 更新数据库中的文件引用
5. 删除旧文件

## 10. 迁移测试策略

### 10.1 单元测试

每个迁移脚本必须编写对应的测试：

```go
func TestV0002Migration(t *testing.T) {
    // 使用内存 SQLite
    db := setupTestDB(t)

    // 先执行 v1 迁移
    v0001Up(db)

    // 插入测试数据
    db.Create(&model.Book{Title: "Test Book"})

    // 执行 v2 迁移
    assert.NoError(t, v0002Up(db))

    // 验证新列存在且默认值正确
    var book model.Book
    db.First(&book)
    assert.Equal(t, int64(0), book.LastReadAt)

    // 执行回滚
    assert.NoError(t, v0002Down(db))
}
```

### 10.2 集成测试

使用真实数据库快照进行端到端测试：

1. 从生产环境导出数据库快照（脱敏）
2. 依次执行所有迁移
3. 验证最终状态与预期一致
4. 依次执行所有回滚
5. 验证回滚后状态与初始一致

### 10.3 迁移兼容性矩阵

| 从 \ 到 | v1 | v2 | v3 |
|---------|----|----|-----|
| v1 | - | ✅ | ✅ |
| v2 | ⚠️ | - | ✅ |
| v3 | ⚠️ | ⚠️ | - |

✅ = 直接迁移  ⚠️ = 需逐版本回滚

## 11. 应急预案

### 11.1 迁移失败处理

| 场景 | 处理方式 |
|------|----------|
| 迁移事务回滚成功 | 服务正常启动，使用旧版 Schema |
| 迁移事务回滚失败 | 从备份恢复数据库文件 |
| 迁移成功但服务启动失败 | 从备份恢复数据库 + 旧版可执行文件 |
| 备份恢复失败 | 手动修复（提供 SQL 修复脚本） |

### 11.2 数据恢复流程

```
1. 停止服务
2. 定位备份文件: data/.backup/schema_v{N}_{timestamp}.db
3. 校验备份完整性: sha256sum
4. 替换当前数据库: cp backup.db e-library.db
5. 启动服务
6. 验证数据完整性
```

### 11.3 紧急停止迁移

添加环境变量 `SKIP_MIGRATION=true`，服务启动时跳过迁移，直接使用当前 Schema：

```go
if os.Getenv("SKIP_MIGRATION") != "true" {
    migrator.Run()
}
```

用于在迁移导致严重问题时紧急启动服务进行数据抢救。
